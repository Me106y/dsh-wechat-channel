## 相对设计的具体落地

- 当前目标 DSH 组件 0.1.5-rc.2 原生支持图片和文件；普通文件通过 saveFileStream 保存并以 file attachment block 提交，不再依赖路径文本模拟附件。
- Host 数据目录以 DSH_HOME 为根，单实例保护。该版本没有在本插件中使用可依赖的 profile 数据服务，支持显式 dataDir。
- messages 表同时承载 Inbox/Submission/Outbox 字段，结构分层在应用代码中保持；未为单人场景拆出多个同生命周期表。
- 面板采用分页快照和不重叠轮询；未新增 SSE 事件存储。DSH 执行仍订阅原生事件。
- 通过官方 Gateway 的 $events / $events/result 处理桌面和微信审批。发送 ACK 仅表示答复已提交；收到权威的结束广播后再展示已处理。
- Trace 通过公开 sessions.open 打开原生会话；未使用私有接口跳转某个 turn。
- 媒体现在使用有界 Buffer 而非完整流式磁盘传输，峰值内存可能数倍于文件大小，单媒体操作串行。
- 严格允许已核验的 iLink/CDN 主机。遇新 IDC 重定向明确失败，需要补充协议证据；不会将 token 发送到任意新域名。

## 安装后验收步骤

- 在面板扫码并确认本人，选择测试项目会话后启动。
- 微信发一条文本，确认 DSH 同一会话收到、完成后微信收到回复。
- 发纯图片并询问图片内容；确认使用支持视觉的模型。
- 发一个小文本文件，让 DSH读取其中指定内容；再让 DSH生成文件并调用发送附件工具。
- 在桌面同一会话发另一条消息，检查没有自动推送到微信。
- 触发需要确认的操作，在微信回复编号；重复回复应提示失效。
- 停用/恢复连接，重启 DSH，检查消息与附件仍在，旧任务没有重复执行。
- 查看失败和重试状态，确认“不确定”不会自动反复发送。

## 0.2.1 运行与投递修复

已确认并修复真实环境重复 DSH 运行时导致的作用域冲突，详见 runtime-deduplication.md。不是通过关闭浏览器保护解决。发送队列改为任务内分片顺序约束，旧任务的 uncertain 记录不再阻塞新任务。发送故障按 prepare/send 阶段保存脱敏原因，便于区分网络中断与接口未确认。

实际补充修复与验收：

- iLink SendMessageResp 的 ret 可省略（默认零）；不再把正常返回误标 uncertain。网络中断和无效 JSON 仍保持不确定，不自动重发。
- 只对持久化诊断明确记录 Send acceptance not confirmed 的历史误判校正状态；旧的无证据记录保持 uncertain。
- DSH 会话恢复通过 sessionController.resolveAgent，保留原生模型选择与 preset；避免裸 resume 缺失 model 变量。
- 63 项测试通过；真实冷恢复测试保留 standard preset 和模型；实际已完成 5 条文本/附件的 iLink API 接受确认，没有重跑用户任务。手机端实际显示由用户确认。
